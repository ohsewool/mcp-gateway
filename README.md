# MCP Security & Reliability Gateway

[![tests](https://github.com/ohsewool/mcp-gateway/actions/workflows/tests.yml/badge.svg)](https://github.com/ohsewool/mcp-gateway/actions/workflows/tests.yml)

에이전트와 MCP 서버 **사이에 실제로 끼어드는** 프록시. 도구 호출이 서버에 닿기 전에 정책으로 판단하고, 위험한 호출은 사람 승인을 요구하며, 모든 결정을 실행 원장에 남긴다.

```
[클라이언트/에이전트] ──JSON-RPC──> [게이트웨이] ──stdio 또는 HTTP──> [MCP 서버]
                                             │
                                             ├─ 정책: 이 호출을 허용하는가
                                             ├─ 무결성: 서버가 도구 설명을 바꿨는가
                                             ├─ 승인: 사람이 이 호출을 정확히 승인했는가
                                             └─ 원장: 무엇이 언제 왜 실행됐는가
```

```bash
pip install -e .                                   # src/ 레이아웃이라 설치 없이는 import되지 않는다
python3 -m pytest tests/ -q                      # 302 tests
python3 -m mcp_gateway.audit verify <log.jsonl>  # 감사 로그 검증
python3 -m pytest tests/ -q -m "not integration" # 실서버 없이
```

## 무엇을 막는가

**정책 차단** — deny-by-default. 등록되지 않은 도구, 명시적으로 거부된 도구, 형식이 깨진 요청은 서버에 도달하지 않는다. 통합 테스트가 증명하는 것은 에러 응답이 아니라 **파일이 생기지 않았다는 사실**이다.

**rug-pull 탐지** — 서버가 등록 이후 도구의 설명이나 입력 스키마를 조용히 바꾸면 `tools/list` 응답을 차단한다. 도구 설명은 모델이 읽는 지시문이므로, 그것이 바뀌었다는 것은 도구가 바뀐 것과 같다.

**JIT 승인** — 결과가 되돌릴 수 없는 도구는 보류된다. 게이트웨이가 요청 범위의 digest를 계산해 실행 의도를 원장에 기록하고, 사람이 승인하면 1회용 lease가 발급된다. 재시도 시 digest를 다시 계산해 **일치할 때만** 통과한다. 인자를 바꿔치기하면 승인이 무효가 되고, 소비된 lease는 두 번째 실행을 만들지 못한다.

**실패를 실패로 기록** — MCP에서 호출이 실패하는 길은 둘인데 그중 하나만 JSON-RPC 오류다. 프로토콜 수준 실패는 `error` 멤버로 오지만, **도구가 실행되고 실패하면 `error`가 아예 없고** `result.isError: true`에 메시지가 담겨 온다. 최상위 `error`만 보면 실패한 도구가 SUCCEEDED로 원장에 남는다 — 무슨 일이 있었는지 알기 위해 존재하는 기록이 반대를 말하고, 나중의 재시도 판단이 그 위에서 이뤄진다. 실서버로 확인했다: 없는 파일을 읽으면 `error` 없이 `isError`만 온다. 둘을 뭉개지 않고 증적에 구분해 남긴다 — "서버가 요청을 거부했다"와 "도구가 돌고 실패했다"는 읽는 사람에게 다른 대응을 요구한다.

**정직한 타임아웃** — 응답이 없으면 실패로 기록하지 않는다. 요청은 이미 전달됐으므로 부작용이 일어났을 수 있다. `UNKNOWN`으로 분류하고 클라이언트에 reconciliation이 필요하다고 알린다. 재시도를 유도하지 않는 것이 핵심이다.

**중복 키 거부** — `{"path": "safe", "path": "../secret"}`을 파서 두 개가 다르게 읽으면 승인한 것과 실행한 것이 달라진다. 파싱 단계에서 거부한다.

**영속 감사** — `GatewayInterceptor(..., audit_log=AuditLog(path))`로 연결한다. **이 문단은 한동안 거짓이었다**: 로그도 만들어져 있었고 테스트도 있었지만 `transport.py`가 `audit`를 import하지 않았고, 결정은 메모리 리스트에만 쌓였다. 양쪽 절반이 다 지어져 있었고 서로 소개된 적이 없었다.

기록에 실패해도 게이트웨이는 판단을 멈추지 않는다 — 디스크가 찬 것은 로깅 문제이고, 거기서 거부로 전환하면 가용성 문제로 바꾸는 것이다. 대신 `audit_failures`로 드러낸다. **없는 기록은 "아무 일도 없었다"로 읽히기 때문이다.**

결정은 메모리에만 남으면 소용이 없다. 며칠 뒤 "무엇을 시도했고 무엇이 막혔고 통과한 하나는 누가 승인했나"를 묻는 사람은 그 자리에 없었다. 해시 체인 JSONL로 append-only 기록하며, 코어의 증적 export와 같은 형식이라 하나의 검증기로 읽힌다 — **이 문장은 한동안 거짓이었다.** 정규화와 체이닝은 동일한데 무결성 필드 이름만 달라(`record_hash` 대 `event_hash`) 서로의 로그를 변조로 판정했다. 양쪽 이름을 다 받아들이도록 고쳤다. 하나로 통일하지 않은 이유는 이미 쓰인 모든 로그가 무효가 되기 때문이다. 재시작하면 기존 체인을 이어 쓴다.

**끝부분 절단 탐지** — 로그 안의 어떤 것도 "내 뒤에서 무엇이 지워졌는지"를 증언할 수 없다. 그래서 로그의 tip을 코어의 외부 witness에 앵커링한다. 한 번 발행된 tip보다 짧게 끝나는 로그는 그저 작은 것이 아니라 **불완전한 것으로 판별된다**. 실패 차원(체인 파손 / 서명 위조 / 절단 / 롤백)을 각각 이름 붙여 보고한다 — "누가 3번 줄을 고쳤다"와 "당신은 옛날 사본을 보고 있다"는 다른 대응이 필요하기 때문이다.

**양의 제한** — 정책은 호출 하나하나를 판단하므로 "전부 허용되는데 만 번" 하는 남용을 막지 못한다. 토큰 버킷으로 도구별 속도를, 세션 예산으로 총량을 제한한다. 둘을 나눈 이유는 서로 못 막는 것이 다르기 때문이다: 속도 제한은 느긋한 무한 루프를 영원히 통과시키고, 예산만으로는 순간적인 폭주를 못 막는다. 세션은 서로 격리되어 시끄러운 클라이언트가 조용한 쪽을 굶기지 못한다.

## 증거

`tests/test_live_server.py`는 공식 `@modelcontextprotocol/server-filesystem`을 자식 프로세스로 띄우고 실제 JSON-RPC로 대화한다.

| 테스트 | 증명하는 것 |
|---|---|
| `test_denied_call_never_reaches_the_real_server` | 차단된 write 이후 대상 파일이 존재하지 않음 |
| `test_metadata_drift_from_real_server_is_detected` | 등록 기준선과 다른 도구 목록은 차단됨 |
| `test_consequential_write_requires_approval_then_happens_exactly_once` | 승인 전 파일 없음 → 승인 후 1회 생성 → lease 재사용 시 재기록 없음 |

## 코어와의 관계

승인·lease·결과 기록은 이 저장소가 직접 구현하지 않고 [`agent-safety-core`](https://github.com/ohsewool/agent-safety-core)의 실행 원장에 위임한다. 게이트웨이는 `ExecutionAuthority` 포트만 알며, 원자적 lease 소비가 외부 호출보다 **먼저** durable commit된다는 보장이 "동일 lease는 최대 1회 dispatch"를 성립시킨다. 코어가 없으면 정책·무결성 계층만으로도 동작한다 — **이 문장도 돌려본 적이 없었다.** 확인해보니 다섯 개의 코어 의존 테스트 중 하나가 가드 없이 코어를 당겼고, 셋은 `/home/jovyan/work/agent-safety-core`라는 **한 기계의 절대 경로**로 가용성을 판단했다. 다른 기계에서는 그 경로가 없어 조용히 skip되고, 그 기계에서 패키지를 지우면 경로는 있는데 import가 실패해 에러가 난다. 지금은 **코어 없이 251개 통과·5개 skip**이고, 그때 46개는 아예 수집되지 않는다 — skip 수보다 **수집되지 않는 수**가 크다는 것이 이 문장의 요점이다. 코어가 있으면 302개 전부 통과한다. 이 세 숫자는 CI가 재서 README와 대조한다(`tests` 워크플로의 `without-core` 잡). **손으로 적어둔 앞 숫자는 139였고, 그동안 총 개수만 갱신되고 이쪽은 방치돼 있었다** — 워크플로 주석은 또 다른 값(35)을 말하고 있었다. 한 저장소가 같은 사실에 대해 서로 다른 세 숫자를 들고 있었다.

## 자식 서버의 환경

두 번째 서버를 붙이다 결함이 하나 나왔다. `StdioProxy`가 `Popen`에 `env`를 주지 않아 **자식 서버가 게이트웨이의 환경변수를 통째로 물려받았다** — 게이트웨이가 쥔 모든 크리덴셜이, 게이트웨이가 의심하려고 존재하는 그 프로세스에 넘어갔고, 막을 방법이 없었다.

이제 `env`를 지정할 수 있다. 기본값은 바꾸지 않았다 — 대부분의 서버는 `PATH`와 `HOME`이 없으면 시작조차 못 하므로, 기본을 바꾸면 모든 호출자가 깨진다. 새로 생긴 것은 **무엇을 줄지 말할 수 있는 능력**이다.

검증은 자식에게 직접 물어서 한다. 첫 테스트는 "테스트가 만든 딕셔너리에 비밀이 없다"를 확인했는데, 그건 구성상 항상 참이라 아무것도 증명하지 않았다. 지금은 자기 환경을 보고하는 stand-in 서버를 띄워 그쪽 응답을 본다.

## 안전 경계

로컬 격리 환경에서 오픈소스 MCP 서버를 실행하는 것까지가 승인 범위다(`docs/PROJECT_SPEC.md` §1.1). 실서비스·실계정·실크리덴셜·프로덕션 배포는 범위 밖이며, 게이트웨이는 차단할 뿐 공격하지 않는다. 통합 테스트의 서버는 pytest 임시 디렉터리에 갇힌다.

## 전송 방식

stdio(자식 프로세스)와 HTTP(원격 엔드포인트) 둘 다 지원하며, **결정 파이프라인은 공유한다**. `HttpProxy.request is GatewayProxy.request`를 테스트로 고정해뒀는데, 전송을 하나 더 붙이면서 규칙이 슬쩍 약해지는 것이 이런 계층에서 가장 흔한 사고이기 때문이다.

네트워크에서만 생기는 두 가지는 파이프와 같은 원칙으로 다룬다: 타임아웃도, HTTP 오류 상태도 "요청은 전달됐으므로 결과를 모른다"는 뜻이라 실패가 아니라 UNKNOWN이다. 그리고 stdio와 달리 응답 하나만 오므로, id가 안 맞는 응답은 건너뛰지 않고 거부한다 — 귀속할 수 없는 응답이기 때문이다.

## 남은 작업

- **서버 다양화 (일부 완료)** — `@modelcontextprotocol/server-memory`를 추가했다. 부작용이 파일이 아니라 지식 그래프 변경이라, "차단된 호출이 아무것도 바꾸지 않았다"를 디렉터리가 아니라 **서버 자신의 상태를 되읽어** 증명한다. 되돌릴 수 없는 `delete_entities`가 차단 대상이다. 네트워크 호출을 하는 서버는 아직 없다.
- **정책 범위** — 경로는 이제 계층으로 다룬다. `/tmp/work`를 허용하면 그 아래가 덮이고, `/tmp/work-evil`은 덮이지 않으며(문자열 접두사가 아니라 경로 성분으로 비교), `..`이 든 경로는 정규화하지 않고 거부한다. 게이트웨이와 서버가 경로를 다르게 정규화하면 승인한 것과 실행한 것이 달라지기 때문이다. 호스트·명령은 계층이 아니므로 정확 일치를 유지한다 — 하위 도메인이 상위 도메인의 권한을 물려받으면 안 된다.
- **수치 상한** — `QuantityConstraint`로 "이 금액 이하만"을 표현한다. `Decimal`을 쓰는 이유는 이진 부동소수점의 돈은 가끔 틀린 쪽으로 반올림되고, 1센트 어긋난 한도는 결국 누군가 반대편에 서게 되는 한도이기 때문이다. 단위가 다르면 덮지 않는다 — 100 USD가 100 KRW를 덮는 환산은 이 계층이 지어낼 것이 아니다.
- **Windows 검증** — 직렬화 계층이 POSIX에서만 검증됐다.
